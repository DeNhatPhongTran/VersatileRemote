Project Overview: VersatileRemote
Đây là một universal remote control chạy trên STM32F429I-DISCO — một bo mạch nhúng có màn hình cảm ứng LCD 320×240. UI được build bằng TouchGFX (framework GUI của ST cho embedded), theo kiến trúc MVP (Model-View-Presenter).
Những gì project đã có:

TV_Screen: màn hình điều khiển TV (Image 3 — có nút power, volume up/down)
AC_Screen: màn hình điều khiển điều hòa (Image 2 — có nhiệt độ, power, fan)
Add_Device screen (Image 1): màn hình thêm thiết bị mới — có trường Device_{type}_id, Signal_ID, và nút confirm/cancel
DeviceMenu container: thanh danh sách thiết bị bên trái (thấy trong Image 2 & 3 với các mục "Device_x")
ButtonDevice container: từng nút thiết bị trong danh sách
Model (data layer): hiện hoàn toàn rỗng — không có logic, không có data

DeviceType enum đã có:
cppDEVICE_TV = 0, DEVICE_PROJECTOR = 1, DEVICE_AC = 2

Ý của bạn ấy nói gì?
Bạn ấy muốn 2 tính năng còn thiếu logic:
1. Danh sách thiết bị động theo màn hình hiện tại

Bên trái màn hình có list "Device_x" — hiện nó là placeholder tĩnh. Yêu cầu: khi đang ở TV_Screen thì list đó chỉ hiện các thiết bị TV đã lưu; khi ở AC_Screen thì chỉ hiện các thiết bị AC đã lưu. Hiện chưa có logic nào lọc/binding danh sách này với loại màn hình.

2. Add Device screen cần biết đang add cho loại thiết bị nào

Khi user nhấn "+" để thêm thiết bị, màn hình Add_Device hiện ra — nhưng nó không biết đang add TV hay AC hay Projector. Bạn ấy đề xuất: hoặc là truyền context từ màn hình gọi (TV_Screen gọi thì add là TV), hoặc là thêm dropdown chọn loại ngay trong màn hình Add_Device để dễ config hơn.


Bạn cần làm gì?
Đây là roadmap cụ thể theo layer:
Bước 1 — Thiết kế data structure trong Model
Model hiện rỗng hoàn toàn. Cần thêm:
cpp// Trong Model.hpp
struct DeviceEntry {
    char name[32];
    char signalId[32];
    DeviceType type;
};

static const int MAX_DEVICES = 20;
DeviceEntry devices[MAX_DEVICES];
int deviceCount;

// Lấy danh sách theo type
int getDevicesByType(DeviceType type, DeviceEntry* out, int maxOut);

// Add device
bool addDevice(const char* name, const char* signalId, DeviceType type);

// Lấy type đang được chọn (dùng cho Add_Device)
DeviceType selectedDeviceType;
void setSelectedDeviceType(DeviceType t);
DeviceType getSelectedDeviceType();
Bước 2 — TV_Screen / AC_Screen truyền type trước khi navigate sang Add_Device
Trong TV_ScreenPresenter hoặc TV_ScreenView, khi user nhấn nút "+":
cpp// Gọi trước khi navigate
model->setSelectedDeviceType(DEVICE_TV);
application().gotoAdd_DeviceScreen(); // navigate
AC_Screen tương tự với DEVICE_AC.
Bước 3 — Add_Device screen đọc selectedDeviceType
Trong Add_DevicePresenter::activate():
cppDeviceType type = model->getSelectedDeviceType();
view.showDeviceType(type); // hiển thị label "TV" / "AC" / "Projector"
Nếu muốn thêm dropdown chọn type (cách dễ config hơn), bạn thêm một SelectionList hoặc một số nút radio trong Add_Device screen trong TouchGFX Designer.
Bước 4 — DeviceMenu hiển thị list theo type của màn hình hiện tại
Mỗi Presenter (TV, AC) khi activate() được gọi, nó lọc danh sách và truyền vào View:
cppvoid TV_ScreenPresenter::activate() {
    DeviceEntry filtered[20];
    int count = model->getDevicesByType(DEVICE_TV, filtered, 20);
    view.updateDeviceList(filtered, count);
}
TV_ScreenView::updateDeviceList() thì populate các ButtonDevice trong DeviceMenu.
Bước 5 — Lưu trữ (Flash / EEPROM)
Hiện tại để đơn giản thì lưu trong RAM (mất khi reset). Sau này có thể dùng Flash của STM32 hoặc EEPROM emulation để persist.
